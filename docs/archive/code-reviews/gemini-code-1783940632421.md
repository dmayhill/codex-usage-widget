# Codex Usage Widget - Project State & Handoff Review

Reviewing the architectural documents and the explicit goals in `AIHandoff.md`, here is an analysis addressing the "Current task" and overall project health.

## 1. README Reconciliation (High Priority)
The handoff requests a reconciliation of the `README.md` wording. There is a significant discrepancy between the documented installation/packaging paths and the actual repository state:
* **Missing Core Scripts:** `README.md` instructs users to run `.\install-windows.ps1` and `.\scripts\build-exe.ps1`. However, neither of these files appears to exist in the core codebase. 
* **Action Required:** Either commit these missing PowerShell scripts to the repository, or update the `README.md` and `Architecture.md` to reflect the actual manual setup steps required for `uv` and PyInstaller.

## 2. The Untracked Runtime Log (Decision)
Regarding the untracked `codex_usage_widget_runtime.log` mentioned in `ProjectState.md`: 
* **Recommendation:** Add `*.log` to `.gitignore` rather than deleting the file. Having a persistent, ignored diagnostic log locally is invaluable for troubleshooting silent Tkinter crashes, Tcl/Tk environment conflicts, or focus-detection misses during daily agentic harness workflows, ensuring the repository stays clean without sacrificing debuggability.

## 3. Microsoft Store Focus Fallback Validation
The handoff emphasizes validating the uncommitted Microsoft Store focus fallback. 
* The implementation relies on `CODEX_PACKAGE_MARKER = "\\windowsapps\\openai.codex_"` to identify the Store app's foreground process. While necessary due to UWP API restrictions, this is highly susceptible to breaking if the Store package identity changes in a future update. 
* **Action Required:** Ensure the regex title matching (`^codex(?:\s|$)`) is thoroughly prioritized in `codex_has_focus()`. If the foreground process path is completely unreadable (access denied), the widget must fail open to the window title check rather than throwing an unhandled `ctypes` exception.

## 4. Tcl/Tk Environment Cleanup
`Architecture.md` notes that the launcher clears `TCL_LIBRARY` and `TK_LIBRARY` to prevent inherited PyInstaller paths from causing conflicts.
* **Risk:** While effective for launching standard Python from a compiled parent, completely unsetting these variables might break the Python fallback sequence if a portable Python installation relies on them. 
* **Action Required:** In `start-codex-usage-widget.ps1`, consider temporarily caching the original variable states, unsetting them for the widget launch, and restoring them upon exit.

## 5. Release Readiness
`ProjectState.md` correctly identifies the lack of a formal release artifact or CI configuration. 
* **Next Step:** Implementing a basic `.github/workflows/build.yml` to run Ruff (for linting) and trigger the PyInstaller build script on tagged commits would eliminate the manual validation bottleneck and provide a stable `CodexUsageWidget.exe` for immediate deployment.
